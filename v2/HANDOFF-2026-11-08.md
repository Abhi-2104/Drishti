## 9. Things learnt the hard way (don't relearn them)

- NSE historical deals JSON caps every answer at **70 rows**, even for one day; the `&csv=true` download does not.
- SHP percentages exclude depository-receipt shares (C1): base = total − `CustodianOrDRHolder` shares.
- BSE returns an **HTML page** (not 404) for an unpublished bhavcopy; the BSE step asks for NSE's newest day instead.
- Windows file mtimes are too coarse for caching; caches are keyed on content.
- Yahoo returns `INR=X` as `USDINR=X`; Yahoo carries live/weekend bars (dropped, except special sessions).
- Screener: `M&M` arrives as `M%26M`; SMEs have no quarterly table; banks/NBFCs have "Financing Profit" rows.
- NSE quote for SME stocks needs series `SM`/`ST`.
- MoSPI needs legacy TLS renegotiation; NSO's own client disables certificate checks — we do not (`MOSPI` profile).
- SEC: `data.sec.gov` accepts a plain UA; `www.sec.gov` (ticker list, archives) needs a real contact UA.
- Diwali Muhurat (Sun 8 Nov 2026) is a real session; NSE's holiday list marks it `Diwali Laxmi Pujan*`.

## 11. Multi-agent checks and balances — readiness

**Works today:** both Claude Code and Codex in WSL can run `drishti mcp` against the same store (SQLite handles several
readers; jobs are the only writers). Each can call every tool, and market signals accept `as_of`, so an agent can be
asked "what did the macro tide look like on 2026-09-15?" and get only what was known then. US fundamentals are
point-in-time via `as_of`. Fundamentals snapshots (India) are kept per fetch date.

**Not ready (needed for "Codex grades Claude on past data"):**
1. **Decision layer + decision log** — gates (`/entry`, `/exit`, `/screen`, `/macro`, …) that write a structured decision
   (ticker, action, horizon, thesis, invalidation, confidence, signals cited, **agent + model**, `as_of`) to a
   `decision` table. Without it there is nothing to grade.
2. **Date-locked mode** — a store view (or `DRISHTI_AS_OF`) that makes *every* tool, not only signals, return only
   rows known by a date: announcements by publish time, insider by filing time, shareholding by filing date, prices by
   trade date, fundamentals by fetch date (India) / filed date (US), deals by trade date. Also: block live fetches in
   that mode (quote, option chain, live announcements).
3. **Scorer** — for a decision made "as of D", forward returns at D+h from stored prices (adjusted), vs Nifty / sector;
   hit rate and calibration per agent.
4. **Copy of the store for evaluation** in WSL, so tests never write into the live store.

Recommended order: decision log → date-locked mode → scorer → agent harness (the grader prompt). Until then, the only
honest multi-agent test is a **side-by-side read**: both agents answer the same questions with the same tools, and you
compare reasoning and citations by hand (§14 prompt C).
